# AutoSE A3 — Agentic issue-to-PR workflow (roll no. 2024111004)

A GitHub Actions workflow in which agents turn a labelled issue into a tested PR with an independent
review posted on it. **A person always decides whether to merge.**

## How to trigger the workflow

| What | How | Who |
|---|---|---|
| Full pipeline (stages 1–6) | add the label **`autose`** to an issue, *or* comment **`/autose`** on it | users with write/maintain/admin permission |
| Single-pass variant (experiment 2) | comment **`/autose single-pass`** on an issue | same |
| Review only (seeded PRs, experiment 1) | comment **`/autose review`** (or **`/autose review coupled`**) on a PR whose body says `Fixes #n` | same |
| Rework rounds | automatic: the `post-review` job dispatches the workflow with `mode=rework` (≤ 2 rework rounds) | workflow |
| Manual / experiments | *Actions → AutoSE → Run workflow* (`workflow_dispatch`) | write access |

Follow a run: the issue gets an ack comment with the run link → the Actions run has the artifacts
`autose-issue-<n>-r<round>` (spec.md, design.md, diff.patch, test_report.md, state.json,
usage.jsonl, agent tool logs) → the PR body (`pr.md`) summarises them → the review is posted as a
PR review comment and the issue keeps a state comment.

## Design in one paragraph

Five LLM agents with separate sessions, prompts and tool sets (Analyst, Architect, Builder,
Tester, Reviewer), plus deterministic code for everything that needs no judgment: the Controller
state machine makes every pass/fail and back-edge decision, and Release pushes and opens the PR.
The model key lives only in jobs whose `GITHUB_TOKEN` cannot write. The jobs that can write never
run a model. The Reviewer runs in its own job on a fresh runner with a different model and a
read-only token, and sees only the issue, the diff and the repository at the PR head. Stage
artifacts are kept off the PR branch so the Reviewer cannot read them. See
`architecture/decisions/`.

## Safety and cost

* The model key is a repository secret (`GEMINI_API_KEY`). It is never in code, logs or prompts. Model-written
  code runs as an unprivileged sandbox user with an empty environment (ADR-005/009).
* Per-run token cap (`AUTOSE_TOKEN_CAP`, default 2M), step budgets per agent, per-job timeouts (ADR-009).
* All Gemini keys are **free-tier keys with no billing account attached**, so no money can be spent (the hard
  limit is the free quota itself). Total usage over all runs: **3,374,817 tokens in 467 model calls**
  (summed from every run's `usage.jsonl`, see `results/summary.md`).
* The workflow only acts on the fork. It never merges, and it posts reviews as `COMMENT`, never `APPROVE`.

## AI use

Following the course policy: a coding agent (Claude Code) helped substantially with this assignment.
It drafted the workflow YAML, the agent harness (`autose/`), the helper scripts, the hidden
tests and seeded PRs, and first drafts of the views and ADRs.

**Review.** I reviewed the AI-generated code line by line and gave suggestions on the ADRs while they
were being written. I did not change the ADR decisions afterwards, because each decision taken in them
reflects the decision I would make myself. All runs, PRs and reviews listed in `results/runs.md` are real
GitHub Actions runs and are generated from the GitHub API.
