# ADR-001 — Five role agents plus deterministic code, not one agent and not one agent per stage

- **Status:** Accepted (design-time, 2026-11-20)
- **Decision area:** D1 Splitting the work

## Context

The workflow has six fixed stages. Each stage needs a different *context*:
- Requirements needs the issue and the A1 skill.
- Design needs `ARCHITECTURE.md`.
- Implementation needs write access.
- Testing should not be anchored on the implementation.
- Review must be independent.

Stages also differ in how much judgment they need. Pushing a branch and opening a PR needs none, but
it needs a token that can write to the repository. In A2 a single agent that wrote both the code and
its own checks tended to confirm its own assumptions. Our hidden tests caught failures that its own
tests did not.

## Decision

We use **five LLM agents, each a separate model session with its own system prompt and tool set**,
plus **two deterministic components**:

| Agent | Stages | Why a separate session |
|---|---|---|
| Analyst | 1 | Loads the A1 skill. Must not think about code yet (the A1 skill forbids design). |
| Architect | 2 | Loads ARCHITECTURE.md. Works from the spec, not the raw issue. |
| Builder | 3 | The only agent with write access to `tinydb/`. |
| Tester | 4 | Writes tests from the acceptance criteria, reading the **base** commit, so the tests are an oracle that is independent of the Builder's code. |
| Reviewer | 6 | Must be independent (ADR-008). Different job, model and token. |
| Controller (code) | all checks, back-edges | Decisions about pass/fail and budget must be reproducible. |
| Release (code) | 5 | Needs a write token but no judgment, so no LLM touches the write token. |

## Alternatives considered

- **One agent for everything** (a single long ReAct loop). It is the cheapest to build, and a single
  context avoids hand-off loss. But the context fills with code before review, the agent grades its
  own work, and tool permissions have to be the union of all stages, so the writer could also push.
  It also has no natural place to enforce stage checks.
- **One agent per stage (6 LLM agents).** Stage 5 does not benefit from an LLM: pushing and opening a
  PR are deterministic, and an LLM holding `contents: write` is the largest injection risk. So we
  replaced that agent with code.
- **Merging Builder and Tester** (the agent writes code and tests). We rejected this because tests
  written by the same session encode the same misunderstanding. It is the cheapest option and is a
  plausible variant to measure.

## Consequences

- Five prompts to maintain, and five hand-offs that can lose information. ADR-003 decides what crosses
  each hand-off.
- Each agent's tool set can be minimal (ADR-005).
- The Tester can write a test that is itself wrong. The Builder cannot "fix" it because it cannot
  write to `tests/`, so a wrong test makes the run go back to design and then stop. That is
  conservative. We accept a lower pass rate rather than tests that just mirror the code.
- More model calls than a single agent. Cost is bounded by ADR-009 budgets.
