# ADR-003 — Hand-offs are full artifacts on a need-to-know basis, never transcripts

- **Status:** Accepted (design-time, 2026-11-20)
- **Decision area:** D3 Hand-offs

## Context

Each hand-off can either lose information (summaries) or leak it (transcripts). Leaking matters in
three places:
1. The raw issue text is untrusted and can carry injected instructions (ADR-009).
2. The Tester should not be anchored on the Builder's code.
3. The Reviewer must not see the implementer's reasoning (assignment requirement, ADR-008).

## Decision

Agents never receive another agent's conversation. They receive **whole artifacts** (no summaries),
chosen per agent:

| To | Receives | Left out, and why |
|---|---|---|
| Analyst | Issue title + body inside a nonce-delimited `<untrusted_issue>` block; the condensed A1 skill; read-only repo | ARCHITECTURE.md (the A1 skill forbids design decisions in a spec) |
| Spec judge | spec.md only | Issue text (it judges testability, not intent; less injection surface) |
| Architect | spec.md, ARCHITECTURE.md, issue *title*, read-only repo | Raw issue body. The spec is the contract and an injection would have to survive the Analyst first. |
| Builder | spec.md, design.md, read/write repo; on a retry also the failing pytest output (truncated tail) or the review findings | The Tester's test file contents while implementing (it can read the file only after the Tester has run, never write it), and the hidden tests |
| Tester | ACs from spec.md, the `Public interface` section of design.md, repo **at the base commit** | The Builder's diff and reasoning. Tests must follow the spec, so a red-on-base / green-on-head result means something. |
| Reviewer | Issue title + body, `git diff base...head`, repo checked out at PR head, can run code | spec.md, design.md, test_report.md, pr.md, PR body, commit messages written by agents (kept neutral), any transcript |
| Release | the git bundle + all artifacts (to build pr.md) | — (no LLM) |

Feedback on back-edges is a *structured excerpt* written by the Controller, not free text from another
agent:
- after failing tests: the tail of the pytest output (up to 5,000 characters);
- after a review: the findings from `verdict.json` (severity, target, file:line, problem, suggestion)
  and the requirements the reviewer marked not met, but not the reviewer's summary prose or tool log.

The Tester runs its own tests only against the base commit, so it never learns whether they pass on
the Builder's code.

## Alternatives considered

- **Shared conversation / scratchpad for all agents.** Simplest, and nothing is lost. It breaks
  independence and spreads injected text to every stage.
- **LLM-written summaries between stages.** Cheaper in tokens, but summaries drop the details that
  later checks depend on, such as exact AC wording and function names. Our artifacts are small (a few
  KB), so full artifacts cost little.

## Consequences

- Each agent's input is reproducible from the artifact store: the artifacts of a run are exactly what
  the next agent received, and the per-agent tool logs (`agent_logs/`) show what each agent read.
- Without the issue body, the Architect cannot recover intent the Analyst missed. Spec errors flow
  downstream until the Reviewer, who does read the issue, catches them.
- The Tester cannot see a new function's real signature, only the one design.md promises. If the
  Builder deviates from the design, tests fail and the run goes back, which is the behaviour we want.
