# ADR-004 — State lives in workflow artifacts plus one state comment, never on the PR branch

- **Status:** Accepted (design-time, 2026-11-20)
- **Decision area:** D4 State

## Context

Three things need to persist:
- Information passes between stages inside a run (in memory or on disk inside the `agents` job).
- It passes between jobs (`agents` → `release`, `review` → `post-review`).
- It passes between runs: review rounds are separate runs (ADR-002), and a run can be restarted.

The assignment requires the Reviewer to see "the repository at the latest commit of the PR". So
anything committed to the PR branch is visible to the Reviewer.

## Decision

- **Within a job:** the run directory `.autose-run/` (git-ignored) holds the artifacts and `state.json`.
- **Between jobs and runs:** each run uploads one workflow artifact `autose-issue-<n>-r<round>`:
  - spec.md, design.md, diff.patch, test_report.md, pr.md (from release), state.json, usage.jsonl;
  - a `branch.bundle` (git bundle of the work branch).

  The review job uploads `review-<n>-r<round>` (review.md, verdict.json, usage.jsonl).
- **Pointer:** one issue comment containing `<!-- autose-state {json} -->` that Release/Poster upserts.
  It holds the latest run id, round, branch, PR number and per-stage status. A rework run reads this
  comment to find the previous run's artifacts (`actions/download-artifact` with `run-id`).
- **Human-readable copy:** every stage result is also posted as a collapsed section in an issue comment.
  The PR body (`pr.md`) links the run. Anyone can follow a run without downloading zips.
- **Nothing from the pipeline is committed to the PR branch** except the code change and the new test
  file. The Reviewer's checkout therefore contains no spec, design or reasoning. As a second line of
  defence the review job deletes `.autose-run/` if it is present.

## Restart behaviour

- *Re-running a failed `agents` job* restarts the Controller from scratch for that round. Artifacts
  are per-run, so nothing half-finished is reused. This is wasteful but always consistent.
- *Re-running `release`* is idempotent: the branch is force-pushed with `--force-with-lease`, and an
  existing open PR for the branch is updated instead of a second one being created.
- *Re-running `post-review`* checks the state comment's round counter before dispatching, so a re-run
  cannot start two round-2 reworks.
- *A new `/autose` comment on an issue that already has an open AutoSE PR* starts round 1 over on the
  same branch (the maintainer asked for it explicitly).

## Alternatives considered

- **Artifacts committed under `.autose/` on the PR branch.** The diff shows everything and it survives
  forever. But the Reviewer would see the implementer's spec and design and its independence would be
  gone. It also makes the PR noisy.
- **A separate orphan `autose-state` branch.** Durable and versioned. But it needs `contents: write`
  in more jobs, and an agent that can run git could read it.
- **Actions cache.** It is not meant for correctness-critical state: it can be evicted and keys are
  scoped by branch.

## Consequences

- Workflow artifacts expire after 90 days by default. `results/` keeps copies of the artifacts we report.
- Reading artifacts from another run needs `actions: read` in the `agents` job.
- If the state comment is edited by a human, a rework run may pick the wrong round. The Poster
  re-derives the round from labels as a cross-check.
