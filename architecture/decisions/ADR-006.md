# ADR-006 — Gemini Flash for the worker agents, a different and stronger Gemini model for the Reviewer

- **Status:** Accepted (design-time, 2026-11-20)
- **Decision area:** D6 Models

## Context

We use Google Gemini (team decision: an API key on the Gemini API with a project spending cap). There
are four worker roles plus a spec judge, and each run makes many short tool-calling turns. Rate limits
(requests per minute) are a real constraint on a student budget. The Reviewer is the last automated
line of defence, and its value comes from *not* sharing the implementer's blind spots.

## Decision

| Role | Model (repo variable, default) | Why |
|---|---|---|
| Analyst, Architect, Builder, Tester, Spec judge | `AUTOSE_WORKER_MODEL` = `gemini-2.5-flash` | Good function calling, fast, cheap per token, high RPM. tinydb changes are small. |
| Reviewer | `AUTOSE_REVIEWER_MODEL` = `gemini-2.5-pro` | Stronger reasoning for finding defects, and a **different model** from the one that wrote the code, so errors are less correlated. One call chain per round, so the cost is bounded. |

- The model ids are repository variables, not code, so we can switch (e.g. to a newer Gemini
  generation) without a commit. The `agents` job lists the available models at start and fails fast
  with a clear message if a configured id does not exist.
- Temperature 0.2 for the agents and 0 for the spec judge. Every call logs `usage_metadata` to
  `usage.jsonl` (prompt, output and thinking tokens), which gives the token totals in the report.

## Alternatives considered

- **Pro for everything.** Possibly a higher stage pass rate, but around 4–8× the cost and lower rate
  limits. That makes multi-issue experiments slow and risks hitting quota in the middle of a run.
- **Same model for the Reviewer.** Simpler and cheaper. But a same-model reviewer tends to accept code
  it would itself have written. We test this directly in a decision experiment (reviewer variant B).
- **A different vendor for the Reviewer** (e.g. Claude). It would maximise independence, but it needs
  a second API key and budget. The assignment does not require it.

## Consequences

- Two models share one rate limit pool per project. Backoff handles 429s (ADR-009).
- If Pro is not available on the key's tier, the Reviewer variable can be set to the strongest model
  that is available. Any such change is recorded in `results/runs.md` per run.
